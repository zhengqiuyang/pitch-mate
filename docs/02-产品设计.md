# 02 · 产品设计 【提案】

## 核心循环（一个练习会话的生命）

```
选场景 → 配客户人设 → 陪练对话（语音/文字，5-20 分钟）
   → AI 客户按剧本推进（挑刺/砍价/拉扯/成交或翻脸）
   → 评分报告（多维度 + 逐句高亮）→ 薄弱点进间隔重复复训队列
```

与 interview-mate 的循环（选题→模拟面试→评分→SRS 复习）同构，UI 心智可平移。

## 场景矩阵（MVP 取前 6 个）

| 场景 | AI 客户剧本核心 | 考察点 |
|---|---|---|
| 冷启动电话 | 前 30 秒就想挂断，三次尝试给钩子机会 | 开场价值主张、破冰 |
| 需求挖掘 | 说的全是伪需求，真痛点藏在细节里 | 提问率、倾听、追问 |
| 产品演示 | 不停被打断+拿竞品对比 | 控场、差异化表达 |
| 异议处理 | "太贵了/我用惯XX了/再考虑下" 连环输出 | 异议应对结构（认同-拆解-重构） |
| 逼单谈判 | 拖延+压价+要额外条款 | 收尾技巧、让步策略 |
| 老客户续约 | 上次交付出过事故，情绪不满 | 挽回、期望管理 |

每场景 3 档难度（温和/标准/地狱），地狱档含"客户说谎"（预算/竞品报价），考察识别能力。

## 人设系统（roleplay-core 直接复用 + 扩展）

人设 = 基础属性（行业/职位/性格大五维度量化）+ 立场参数（预算真实性、时间压力、
竞品倾向、决策权）+ 剧本锚点（必须触达的 3-5 个剧情节点，如"中途接电话说竞品便宜 30%"）。

与面试官人设的关键差异：**客户有隐藏信息**（预算/决策链/真实痛点），玩家通过提问才能解锁——
这是"需求挖掘"场景的可玩性来源，也是评分数据里最值钱的信号（提问率 vs 陈述率）。

MVP 内置 12 个人设（场景×难度组合），旗舰版开放"导入真实客户画像"（脱敏后生成定制人设）。

## 评分体系（产品差异化核心，对标 Hyperbound 的 SIM score）

五维评分（每维 0-100，附逐句证据）：

| 维度 | 信号来源 |
|---|---|
| 开场与破冰 | 前 3 轮对话的钩子质量、语速节奏 |
| 提问与倾听 | 提问率、开放题占比、对客户信息的引用复述 |
| 异议应对 | 异议出现后的应对结构完整度、情绪稳定性 |
| 价值传递 | 提到客户痛点的次数与相关度（人设真痛点命中） |
| 推进与收尾 | 下一步动作明确性（约到下次会议/成交/合理止损） |

评分由 LLM 按结构化 rubric 打分 + 规则引擎交叉校验（提问率等硬指标不依赖 LLM 判断）——
沿用 interview-mate"LLM 判断软指标、确定性代码算硬指标"的分工原则，防止单点幻觉。

## 复盘产品

- **逐句时间轴**：对话回放，问题句标红（"这里陈述多于提问"）、亮点句标绿；
- **对比模式**：同一场景两次练习的维度雷达图对比（进步可视化——给销售总监看的留存钩子）；
- **团队看板**（团队版）：成员维度均值、薄弱项排行、练习频次——主管每周 5 分钟看完。

## 语音交互（v0.1 含，MVP 验证重点）

- 浏览器 WebRTC 采集 + 云端 ASR/TTS（国内：ASR 选大厂流式 API；TTS 需支持"不耐烦/迟疑"情感参数）；
  备选：微信小程序 + 同声传译插件（doodle-story 已验证该链路）；
- 延迟预算：用户说完 → AI 客户开口 ≤1.5s（流式 ASR 边听边转 + 首 token 流式合成）；
- 文字模式全程保留（地铁里也能练，且是免费层形态）。

## 明确不做（M0 拍板，防 scope 蔓延）

- 不做真实客户对话分析（那是 Gong/循环智能的战场，需要 IM 集成，别碰）；
- 不做 CRM 集成（v1 之后再说）；
- 不做多语言（中文 only，英文市场让给海外竞品）。
